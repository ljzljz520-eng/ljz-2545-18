# 街区章节（Neighborhood Chapters）设计说明书

> 范围：为站点新增“街区”章节。网页提供**历史背景、停留点、路线入口**；
> 服务层维护**章节树**与**路线关联**；PostgreSQL 储存**发布版、别名与迁移关系**。
>
> 代码索引：
> - 数据库迁移：`server/db/migrations/0001_neighborhood_chapters.sql`
> - 服务层：`server/src/{chapterService,neighborhoodService,routeService,cache,permissions,store}.js`
> - 验收测试：`server/test/acceptance.test.js`（12 例）、`server/test/frontend.test.js`（7 例）
> - 网页：`neighborhood.html`、`js/neighborhood.js`、`css/neighborhood.css`

## 1. 核心建模决策

### 1.1 章节树只在“章节自身”检查循环

- `chapter.parent_id` 表达层级，街区章节是 `kind = 'neighborhood'` 的章节。
- 循环检测只沿章节自己的 `parent_id` 链向上走：
  - 服务层 `ChapterService.assertNoCycle`（移动前递归祖先链）；
  - 数据库层 `chapter_tree_guard` 触发器（递归 CTE 兜底），两者一致。
- 路线**不在章节树内**，因此“路线跨多个街区”永远不可能制造章节循环，也没有“唯一父节点”负担。

### 1.2 路线不挂单一街区外键——独立关联表（方案对比与结论）

| 维度 | 方案 A：`route.neighborhood_id` 单外键 | 方案 B（采用）：`route_neighborhood` 关联表 |
|---|---|---|
| 跨区路线 | 无法表达，只能伪造“主街区”或复制路线 | 天然多对多，一条路线挂多个街区 |
| 主要/次要入口 | 唯一外键即唯一入口，次要入口无处安放 | `role=primary/secondary`，主次同表 |
| 街区边界调整 | 外键仍指向旧街区，语义上被迫“永远继承” | 关联单独置 `review_pending`，可保留/改派/解除 |
| 拆分路线 | 要么删外键丢历史，要么复制行产生双主线 | 按关联分组拆，旧路线与新路线由 `route_migration` 串起 |
| 删除街区 | 单条外键要么 RESTRICT 要么 SET NULL 丢信息 | 逐条解除/改派，引用清单可精确列出 |
| 唯一性约束 | 简单 | 用部分唯一索引保证“每路线至多一个 active 主入口” |

**结论**：采用方案 B。方案 A 唯一的优点（写起来少一张表）在“跨区 + 复核 + 拆分”三个硬需求下全部变成负债。

关联表关键约束：

```sql
UNIQUE (route_id, neighborhood_id);
CREATE UNIQUE INDEX route_one_active_primary_uidx
  ON route_neighborhood (route_id)
  WHERE role='primary' AND state='active';
```

### 1.3 发布版、别名、迁移关系（PG 持久化）

- **发布版**：`chapter_revision` 为不可变快照（标题/摘要/历史正文/发布时刻的祖先链 `tree_path`）。
  草稿直接改 `chapter` 行；发布才追加版本号，`chapter.current_revision_id` 指向最新发布版。
  面包屑与路线入口按已发布版本一致渲染，移动章节不会改写历史快照。
- **别名**：`chapter_alias` 全局唯一。深链接命中别名→真实章节（301 语义）；
  目标已撤回时返回 **410 + 替代指向**，绝不静默改派到别的章节。
- **迁移关系**：`chapter_migration(kind=move|merge|split, from, to)` 与
  `route_migration(kind=split, from, to)`。移动只记审计；合并/拆分是结构性重定向依据。

## 2. 网页层

页面 `neighborhood.html` 分三区：

1. **面包屑**：从最近一个“当前用户可见”的祖先开始渲染，未公开层不出现（与后端权限同构）。
2. **侧栏**：章节树（仅 `published`）+ 筛选（时代、仅看停留点）。
3. **主区**：历史背景、停留点（锚点）、路线入口（按“主要展示入口 / 次要入口”分组），
   边界复核挂起的关联显示复核提示，不再展示为可用入口。

### 2.1 主要展示入口与次要入口

- 每条已发布路线**恰好一个** `active + primary` 关联；其余为 `secondary`。
- 解析顺序（`RouteService.resolveEntry` / SQL `resolve_public_route_entry`）：
  `primary` → 其余 `secondary`（按 `sort_order, id` 确定性排序）；都不可用 → 显式 `gone`。
- 主要入口因边界修改进入 `review_pending` 时，公开访问自动回落到第一个可用次要入口，
  **不按旧中心点猜归属**；待复核关联在复核完成前也不允许被重新设为 primary。

### 2.2 撤回后的替代指向

路线撤回必须显式给出替代之一，否则明确 410：

1. `fallback_route_id`：接续/拆分出的新路线（302/301 到新路线）；
2. `fallback_chapter_id`：退回某个已发布街区章节；
3. 都没有：**410 Gone**，页面展示“已撤回、无可用入口”，而不是跳去首页或随机街区。

章节侧同理：合并/拆分走 `chapter_migration` 重定向；纯撤回返回 410 + `fallback`。

### 2.3 浏览者返回：恢复来源章节、筛选、滚动锚点

状态保存在 `sessionStorage`（键 `neighborhood:browse-state:v1`）：

```js
{ chapterRef, era, stopOnly, anchor, scrollY, sourceRoute }
```

- 点停留点、切筛选、滚动（节流 100ms）、跳路线前均写入；
- 返回页面且 URL 无显式参数时，`resolveInitialState` 读取并恢复，横幅提示“已恢复上次浏览”。

### 2.4 深链接没有历史记录也有确定入口

URL 支持：`?ch=city/old-town`（路径）、`?ch=old-town`（裸 slug）、`?alias=laochengxiang`、
`?route=heritage-walk`，并可带 `era / stopOnly / anchor`。

解析优先级（`js/neighborhood.js#resolveInitialState`）：

1. 显式 `ch/ref/alias` → 章节解析（别名给 redirect，撤回给 gone+fallback，草稿 404）；
2. 显式 `route` → 路线入口解析（主要/次要/重定向/gone）；
3. 无显式参数但有 saved → 恢复；
4. 首次访问 → 目录默认入口（取第一个 published，确定性）。

### 2.5 回包乱序防护

`ResponseGuard` 为每个 key 维护单调序号：`begin()` 领号，回包到达时 `isCurrent(key, seq)`
校验，旧序号响应直接丢弃，避免“慢的旧面包屑覆盖新章节树”。章节树另用 `TreeCache`
按 `tree_version` 失效，章节移动/发布/撤回后全量 bust。

## 3. 服务层

| 服务 | 关键方法 | 职责 |
|---|---|---|
| `ChapterService` | `create / move / assertNoCycle / breadcrumb / publish / withdraw / addAlias / recordMerge / resolveRef` | 章节树、循环检查、乐观锁、发布版本、别名与深链接解析 |
| `NeighborhoodService` | `register / page / addStop / changeBoundary / resolveReview / delete` | 街区资料、停留点、边界变更复核、引用保护 |
| `RouteService` | `createRoute / associate / setRole / publish / withdraw / resolveEntry / splitRoute` | 多对多关联、主次入口、撤回替代、跨区拆分 |
| `permissions` | `canViewChapter / canEditChapter / canPublish` | 面包屑、街区页、路线入口共用同一可见性判定 |

### 3.1 两个编辑同时移动章节（乐观锁）

- `chapter.tree_version` 每次 `parent_id` 变更自增（触发器与服务层都维护）。
- `move(user, id, newParentId, expectedVersion)`：版本不符抛 `CONFLICT`，
  前端需重读后重试，杜绝后写覆盖先写。PG 侧还可用 `SELECT ... FOR UPDATE`/咨询锁串行化树编辑。

### 3.2 街区边界修改后“复核而非继承”

`changeBoundary` 在同一事务内：

1. 更新 `neighborhood.boundary`、`boundary_version += 1`；
2. 对每条 `active` 关联写一条 `boundary_review`（存旧/新边界），并把关联置 `review_pending`。

`resolveReview(decision)` 三种结论：

- `keep`：恢复 active；
- `reattach(target)`：校验无重复关联后**真正改写** `neighborhood_id`；
- `detach`：永久解除。

系统不依据“旧中心点落在哪”自动改派——地理归属必须人工确认。

### 3.3 删除仍被引用的街区

`NeighborhoodService.delete` 列出所有非 detached 的路线关联（及停留点），
抛 `REFERENCED` 并附带 `routeIds`；管理员须先逐条 `detach/reattach`、清空停留点后才能删。
数据库外键同样是 `ON DELETE RESTRICT` 兜底。

### 3.4 跨区路线拆分

`splitRoute(routeId, groups)`：

- 校验：分组覆盖**全部**当前关联且不重叠；每组至多一个 primary；新 slug 不冲突（写前预检）；
- 执行（PG 为单事务，内存实现带补偿回滚）：每组生成一条已发布新路线，
  继承旧关联主次角色，无 primary 的组把首个街区提升为新主入口；
- 旧路线置 `withdrawn`，`fallback_route_id` 指向第一条新路线，并为每个目标写 `route_migration`。
  旧链接因此有确定 301 去向，不会断链。

### 3.5 权限与防泄漏

- 角色：`visitor`（仅 published）/ `editor`（负责章节集合内可见草稿）/ `admin`（全权 + 发布）。
- 面包屑、街区页路线列表、路线入口解析**共用** `canViewChapter`：
  - 关联对端章节是草稿/撤回 → 该关联在公开接口被过滤；
  - 路线发布前校验所有关联街区章节均已 published，否则拒绝发布；
  - 草稿路线/草稿章节对访客与非负责编辑一律返回 404（不暴露存在性）；
  - 撤回是公开生命周期事实，返回 410 + 可选替代，不暴露正文。
- 结构性重定向只在“引用确实等于源章节旧 slug/别名”时触发，
  避免把合并**目标**章节错误地自引用重定向（该细节在深链接测试中固定）。

## 4. 数据模型一览

```
chapter (kind=neighborhood|section, parent_id 自引用, status, tree_version, current_revision_id)
  ├─ chapter_revision  (不可变发布快照, tree_path 祖先链)
  ├─ chapter_alias     (别名, 全局唯一)
  └─ chapter_migration (move|merge|split)
neighborhood (1─1 chapter, boundary JSONB, boundary_version)
  └─ stop (停留点)
route (status, fallback_route_id, fallback_chapter_id)
  ├─ route_neighborhood (M:N, role primary|secondary,
  │                      state active|review_pending|rejected|detached,
  │                      pending_neighborhood_id)
  ├─ boundary_review    (边界变更复核单)
  └─ route_migration    (split 接续关系)
```

## 5. HTTP 语义（适配层映射建议）

| 场景 | 状态码 | 说明 |
|---|---|---|
| 章节/路线正常入口 | 200 | `entry/primary/secondary` |
| 别名、合并、拆分、路线接续 | 301（结构性）/302（临时） | `Location` 指向目标 |
| 已撤回无替代 | 410 Gone | 响应体可带 `fallback` |
| 草稿/无权/不存在 | 404 | 对访客统一文案，不区分 |
| 移动版本冲突 | 409 Conflict | 带 `currentVersion` |
| 街区仍被引用 | 409 Conflict（`REFERENCED`） | 带 `routeIds/stopIds` |
| 章节循环 | 409（`CYCLE_DETECTED`） | |
| 发布校验失败 | 422/400 | 主入口不唯一/对端未公开等 |

## 7. 未来扩展

- 边界改用 PostGIS `geometry(Polygon, 4326)` + GiST 索引，复核单可叠加空间差异分析。
- 章节树读多写少时，用 `ltree` 物化路径加速后代查询（循环检查仍保留）。
- 发布走审批流时，`chapter_revision` 增加 `review_state` 与审批人链。
- 路线入口可按用户角色/语言返回不同次要候选，但主入口唯一性规则不变。
