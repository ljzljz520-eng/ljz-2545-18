# 街区章节 · 设计文档

## 1. 功能范围

- **网页**：`districts.html`（街区列表）、`district.html`（街区详情：历史背景 / 章节树 / 停留点 / 路线入口）、`route.html`（跨区路线详情）。
- **服务层**（`server/src/services.js`）：维护章节树与路线关联，处理移动、复核、拆分、撤回。
- **PG 存储**（`server/sql/schema.sql`）：发布版（`chapter_publications`）、别名（`chapter_aliases`）、迁移关系（`chapter_migrations` / `route_migrations`）。

## 2. 核心决策：路线中存单一街区 vs 独立关联表

| 维度 | 方案 A：routes.district_id 单一字段 | 方案 B：独立关联表 route_districts（采用） |
|---|---|---|
| 跨区路线 | 无法表达，只能强制唯一父节点，把跨区路线拆散或重复建路线 | 天然多对多，一条路线关联多个街区 |
| 主/次入口 | 无法区分 | 关联行 `role=primary/secondary`，部分唯一索引保证每条路线至多一个主要展示入口 |
| 撤回替代 | 需额外字段且语义混杂 | 关联行 `fallback_route_id`，替代指向随关联走 |
| 边界复核 | 无落点 | 关联行 `needs_review` + 复核队列表 |
| 查询成本 | 一次单表查询 | 多一次 JOIN（以街区/路线为主键的索引可控制在毫秒级） |
| 一致性维护 | 简单 | 需要复核队列与撤回联动，服务层统一收口 |

**结论**：采用方案 B。路线可以跨多个街区，不能强制唯一父节点；关联表是唯一能不丢信息地表达"主要展示入口、次要入口、撤回后的替代指向"的结构。单一字段方案在本需求下会把跨区路线错误地压成树，违背业务现实。

**对照**：章节自身是树（唯一 `parent_id`），只有章节移动时才检查层级循环（目标父链不得包含自身）；路线 ↔ 街区是图（多对多），无父子概念，不做循环检查。

## 3. 边界修改：复核而非继承

街区边界修改后，`boundary_version` 递增，服务层对该街区的**所有现存关联**生成 `route_district_reviews`（pending）并把关联标记 `needs_review=true`：

- 复核确认（confirmed）→ 清除标记，关联保留；
- 复核移除（removed）→ 删除关联行；
- 复核期间前台展示"边界复核中"标记，**不按旧中心点永远继承**——中心点只是修改时刻的快照，边界变化后停留点与街区的空间关系必须重新确认。

## 4. 并发与一致性

- **两个编辑同时移动章节**：`chapters.version` 乐观锁。请求携带 `baseVersion`，先提交者成功（version+1），后到者收到 `409 VERSION_CONFLICT`，响应体携带当前最新状态（当前版本号与父节点），客户端提示"已被他人修改"并展示最新位置。
- **删除仍被引用的街区**：`DELETE /api/districts/:id` 检查 `route_districts` 与章节，存在引用时返回 `409` 与引用清单（路线 id / 标题 / 状态 / 入口角色），引导先解除关联或撤回路线，不做级联硬删。
- **跨区路线拆分**：`POST /api/routes/:id/split` 按停留点所属章节的街区分组，每组生成新单区路线（关联为 primary），原路线状态置 `split` 并设置 `fallback_route_id` 指向主街区新路线，同时写入 `route_migrations`，深链接可重定向。
- **缓存回包乱序**：`VersionedCache` 每次写入分配单调递增 seq；迟到的旧 seq 写入被拒绝；`invalidate` 留下 tombstone，失效后旧包无法复活该键。HTTP 响应携带 `X-Cache-Seq`，前端对每个资源键只接受最新一次请求的响应（`js/district-api.js`），乱序回包直接丢弃。

## 5. 权限与可见性

- 调用者身份经 `X-Role` 头识别（演示级）：匿名只见 `published`；编辑可见 `draft/published/withdrawn`。
- **页面面包屑与后端权限一致**：面包屑由 `GET /api/chapters/:id/breadcrumb` 在后端按调用者权限生成，未公开祖先不出现，但继续向上找可公开祖先，保证有确定入口；前端不自行拼接隐藏节点。
- **未公开章节不得通过路线关联接口泄漏**：`GET /api/routes/:slug` 过滤未公开章节下的停留点，关联街区同样过滤；`visibleStopCount` 等计数基于过滤后的集合，避免通过计数侧信道泄漏；匿名访问 draft 资源返回 404（不泄漏存在性），撤回资源返回 410 + 替代指向。

## 6. 浏览导航：返回恢复与深链接

- **返回时恢复**：列表页在跳转详情前把筛选、搜索词、滚动位置存入 `sessionStorage`；返回时恢复筛选并滚动到原位置。详情页进入路线前记录来源街区，路线页返回时优先回到来源。
- **深链接确定入口**：URL 参数（`?theme=`、`?q=`、`?d=`、`?r=`）可直接打开任意状态；无同站历史记录时，返回按钮回退到确定入口（街区列表 / 主入口街区），并显示"你从外部链接直接进入"提示；章节旧 slug 经别名表解析，已迁移章节经迁移关系重定向，撤回路线经 410 的 `fallbackRouteId` 指向替代路线。

## 7. API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/districts?theme=&q=` | 街区列表（计数按权限过滤） |
| GET | `/api/districts/:slug` | 街区详情：历史背景、章节树、停留点、路线入口（带 `X-Cache-Seq`） |
| GET | `/api/chapters/:idOrSlug` | 章节解析（id / slug / 别名 / 迁移重定向） |
| GET | `/api/chapters/:id/breadcrumb` | 面包屑（权限过滤） |
| GET | `/api/routes/:slug` | 路线详情（主/次入口、停留点；未公开不泄漏） |
| GET | `/api/reviews?status=pending` | 复核队列（编辑） |
| POST | `/api/chapters/:id/move` | 移动章节（循环检查 + 乐观锁） |
| POST | `/api/districts/:id/boundary` | 修改边界 → 生成复核 |
| POST | `/api/reviews/:id/resolve` | 复核结论 confirmed/removed |
| DELETE | `/api/districts/:id` | 删除街区（被引用则 409） |
| POST | `/api/routes/:id/split` | 跨区拆分 |
| POST | `/api/routes/:id/withdraw` | 撤回路线（落实替代指向） |

## 8. 运行

```bash
# 内存模式（含种子数据，无需 PG）
cd server && node src/server.js        # http://localhost:3000

# PostgreSQL 模式
cd server && npm i pg
DATABASE_URL=postgres://user:pass@host:5432/db node src/server.js

# 验收测试（12 个场景）
cd server && npm test

# 完整栈（web + server + db）
docker compose up -d --build
```
